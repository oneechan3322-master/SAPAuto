 §1  WHATSAPP ENGINE — STATUS & LIVE PAIRING PROTOCOL
────────────────────────────────────────────────────────────────────────────────

1. STATUS: ALIVE & HEALTHY (Tested & Verified via Live API)
   The engine boots headless Chromium and produces a genuine QR code.
   Recent fixes and hardenings applied:
     - Bug 1: channels/whatsapp.js:11 — duplicate `const path` declaration removed.
     - Bug 2: `const require = createRequire(__filename)` TDZ shadowing resolved.
     - Bug 3: Hardened Chromium sandbox arguments for Windows background execution:
       `--no-sandbox`, `--disable-setuid-sandbox`, `--disable-dev-shm-usage`,

   - Clean startup log:

 §4  HARNESS AUTOMATION LOOP TESTING (UNDER WATCH)
────────────────────────────────────────────────────────────────────────────────

The harness orchestrates periodic scans, state transitions, quiet hours, and
automatic live AI analysis.

 1. RUN A SINGLE HARNESS PASS MANUALLY:
    Command (the exported API is runCycle — there is no runOneCycle):
      node -e "
        const { runCycle } = require('./harness/loop');
        runCycle().then(r => console.log('Cycle finished:', r));
      "
    Single-account variant:
      node -e "
        const { runCycle } = require('./harness/loop');
        runCycle({ accountKey: 'marwanhamada' }).then(r => console.log('Cycle finished:', r));
      "
    Honesty note: while harness_status.paused=1 a manual cycle exits
    immediately as 'interrupted' (the pause guard at loop.js:91 is by
    design). Un-pause first, then run the manual cycle.

 2. WATCH HARNESS STATUS REAL-TIME:
    Run query (harness_status has no details column — the state fields are
    state / paused / last_heartbeat / account_total):
      node -e "
        const db = require('./db/connect').getDatabase();
        console.table(db.prepare('SELECT account_key, state, consecutive_failures, last_success_at FROM account_status').all());
