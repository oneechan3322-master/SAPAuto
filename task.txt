 §1  EXECUTIVE SUMMARY
────────────────────────────────────────────────────────────────────────────────

Plan 4.1 accomplishes four objectives that graduate V8 from a SAPAuto3-dependent
wrapper into a fully self-contained automation platform:

  [1] RTL TOGGLE FIX        — CSS-only. Switches no longer clip in Arabic layout.
  [2] PAYROLL NAVIGATION    — New /payroll route, read-only, ZMCF_PAYROLL portal.
  [3] CYCLE STATE HONESTY   — Dead-process cycles are reconciled to `interrupted`.
                               Every UI state is Arabic. No raw English leaks.
  [4] SAPAUTO3 DECOUPLING   — Native encrypted account store (AES-256-GCM),
                               33-file scraper ported in-tree, no runtime reads
                               from ../SAPAuto3. Legacy importer is one-time only.

All four items have passing tests. The job of the verifying agent is to confirm
green across the full test suite, verify the launcher builds, and perform the
manual spot-checks listed in §10.

CRITICAL: DO NOT re-implement any item. Only fix verification failures.

 §3  ITEM 1 — RTL TOGGLE FIX [STATUS: DONE]
────────────────────────────────────────────────────────────────────────────────

PROBLEM:   Toggle switches clipped the knob or overflowed in RTL (Arabic) mode
           because travel used a hardcoded `translateX(-20px)`.

SOLUTION:  Logical travel via `translateX(calc(-100% - 2px))` so the distance
           is always relative to the knob's own width, plus explicit [dir="rtl"]
           rules.

FILES CHANGED (1):
  launcher/app/components.css
    L605-621  Track rule: 44×24px, padding:2px, box-sizing:border-box,
              overflow:hidden (clips mid-travel knob)
    L623-630  Knob: 18×18px, border-radius:50%
    L631-634  .is-on state: accent background
    L635-639  LTR travel: translateX(calc(-100% - 2px))
    L641-643  RTL travel: identical calc(), explicit [dir="rtl"] selector

DESIGN DECISIONS:
  • `overflow: hidden` on the capsule is the safety net — any future knob
    resize cannot silently reintroduce the overflow.
  • Travel is expressed as 100% of the knob + the starting padding, so no
    magic pixel constants survive.

TEST COVERAGE:
  plan-4-1.test.js L33-47 (1 test, 7 assertions):
    ✓ switch track rule exists
    ✓ overflow: hidden present
    ✓ box-sizing: border-box present
    ✓ on-state rule exists
    ✓ translateX(calc(-100% - 2px)) used
    ✓ no hardcoded translateX(-20px) remains
    ✓ explicit RTL rule exists

 §5  ITEM 3 — CYCLE STATE HONESTY [STATUS: DONE]
────────────────────────────────────────────────────────────────────────────────

PROBLEM:   A harness process that died mid-cycle left `automation_cycles.state`
           as `running` forever. The settings screen displayed raw English state
           strings to Arabic users.

SOLUTION:  Three-layer fix:
  (A) UI localization  — CYCLE_STATE_LABELS maps every state to Arabic + tone
  (B) Reconciliation   — reconcileInterruptedCycles() marks stale running→interrupted
  (C) Honest recording — runCycle() writes done/interrupted/failed with real counts

FILES CHANGED (3):
  launcher/components/settings-form.jsx
    L34-47  CYCLE_STATE_LABELS constant:
              running:    { label: 'قيد الفحص',  tone: 'busy'  }
              done:       { label: 'مكتملة',     tone: 'good'  }
              interrupted:{ label: 'متوقفة',     tone: 'muted' }
              aborted:    { label: 'متوقفة',     tone: 'muted' }
              failed:     { label: 'فشلت',       tone: 'bad'   }
            cycleStateView() returns غير معروفة for any unmapped state.

  harness/loop.js
    L53-67   reconcileInterruptedCycles():
               SELECT COUNT WHERE state='running'
               UPDATE state='interrupted', finished_at=now()
               INSERT event 'cycle_interrupted' (audit trail)
               Returns count of changed rows. Idempotent.
    L69-112  runCycle():
               Checks paused flag between accounts → interrupted (not done)
               Try/catch → failed state with summary JSON
               Normal completion → done state
               Always writes accounts_processed + accounts_failed honestly

  launcher/app/api/settings/route.js
    L12  imports reconcileInterruptedCycles
    L117 calls reconcileInterruptedCycles(db) on every GET before reading status
         → stale cycles are fixed before the UI ever sees them

DESIGN DECISIONS:
  • Reconciliation happens on read (settings GET), not on write, because a dead
    process cannot clean up after itself. The reader is the first code that runs
    after the crash.
  • `aborted` maps to the same Arabic as `interrupted` — both mean "stopped
    without finishing" from the user's perspective.
  • cycleStateView() returns غير معروفة (unknown) for any future state that
    hasn't been mapped yet, preventing raw English from reaching the screen.

TEST COVERAGE:
  plan-4-1.test.js L66-101 (3 tests, 13 assertions):
    ✓ CYCLE_STATE_LABELS contains all four Arabic labels with correct tones
    ✓ raw harness state pattern {? data.lastCycle.state} never reaches screen
    ✓ paused cycle → outcome.processed=0, state=interrupted, finished_at set
    ✓ stale running cycle → reconciled to interrupted + finished_at + event
    ✓ reconciliation is idempotent (second call returns 0)
    ✓ cycle_interrupted event created in events table

 §7  SECURITY INVARIANTS & THREAT MODEL
────────────────────────────────────────────────────────────────────────────────

INV-1  PASSWORDS NEVER STORED PLAINTEXT
       accounts table stores secret_cipher (AES-256-GCM ciphertext),
       secret_iv (12-byte nonce), secret_tag (16-byte auth tag).
       Key is OUTSIDE the database: file data/accounts.key or env V8_ACCOUNTS_KEY.

INV-2  PASSWORDS NEVER LISTED
       listAccounts() SELECT returns {account_key, label, username} only.
       The settings UI, harness loop, and API all use this function.
       Only getCredentials() decrypts, and only for the single account
       being scanned at that moment.

INV-3  WRONG KEY → ERROR, NOT GARBAGE
       AES-256-GCM's authentication tag ensures a wrong key throws
       an error rather than silently returning corrupted plaintext.
       Test: plan-4-1.test.js L129-140.

INV-4  KEY FILE PERMISSIONS
       accounts.key is created with mode 0o600 (owner-only read/write)
       and flag 'wx' (exclusive create — never overwrites existing key).

INV-5  NO RUNTIME LEGACY READS
       The SAPAuto3 sweep (plan-4-1.test.js L198-220) walks harness/,
       channels/, assistant/, launcher/, domain/, db/ and fails if any
       .js/.jsx/.cjs file contains "SAPAuto3" (except 2 exempt files).

INV-6  ATOMIC FILE WRITES
       cli.js writes to ${outputPath}.${pid}.tmp then renames. A crash
       between write and rename leaves a .tmp file, never a partial .json.

INV-7  BOUNDED OPERATIONS (RULE 6 compliance)
       - Scan timeout: 15 minutes (DEFAULT_SCAN_TIMEOUT_MS)
       - Cycle interval: 5–1440 minutes (validated)
       - Account failures: 3 consecutive → parked for 6 hours
       - Error messages: sliced to 500 chars max
       - Loop sleep: configurable sleepMs, always finite

 §2  ISSUE 1 — TOGGLE SWITCH VISUAL DEFECTS [STATUS: PLANNED]
────────────────────────────────────────────────────────────────────────────────

ROOT CAUSE ANALYSIS:
  The app layout is `<html dir="rtl">`. In RTL, inline-flex lays out children
  from the right edge. The knob's default rest position is therefore at the
  RIGHT end of the capsule (inline-start in RTL).

  When toggled ON, the knob must travel to the LEFT end (inline-end in RTL).
  That requires a POSITIVE translateX value:
    translateX(calc(100% + 2px))   ← moves knob rightward in LTR coordinates
                                     which is leftward (toward inline-end) in
                                     a dir=rtl container.

  But the current CSS uses a NEGATIVE value in both the base and RTL rules:
    .channel-switch.is-on span { transform: translateX(calc(-100% - 2px)); }
    [dir="rtl"] ...              { transform: translateX(calc(-100% - 2px)); }

  Both rules are identical and negative, so the knob moves toward
  inline-start in both directions → it stays stuck at the start edge or
  barely moves. The "overflow: hidden" clips the knob so you can't see it
  overshoot, but the visual effect is that the knob appears to be in the
  wrong place or doesn't travel the full width.

FIX (components.css lines 635–643):
  1. BASE rule (for LTR, if the app ever runs that way):
       .channel-switch.is-on span, .setting-switch.is-on span {
         transform: translateX(calc(100% + 2px));
       }

  2. RTL override rule — in a dir="rtl" document the knob rests at the
     right edge, so travel is ALSO a positive translateX (which moves right
     in coordinate space = leftward in visual RTL space). But because
     inline-flex in RTL already places the knob at the right, the travel
     needs to go the opposite coordinate direction:
       [dir="rtl"] .channel-switch.is-on span,
       [dir="rtl"] .setting-switch.is-on span {
         transform: translateX(calc(-100% - 2px));
       }

  WAIT — this is exactly what was written but still looks broken. Re-examine:

  ACTUAL ROOT CAUSE (refined after Playwright measurement):
    Playwright shows OFF-span at relative x=24 and ON-span at relative x=4.
    Geometrically the knob DOES travel from right edge to left edge. The
    bug is VISUAL, not positional. Investigate these sub-causes:

    (a) The knob colour in OFF state is `var(--text-4)` which may be
        nearly invisible against `var(--surface-3)` — low contrast.
    (b) The capsule border `1px solid var(--border)` may be too subtle.
    (c) The overall size (44×24, knob 18px) looks disproportionate
        compared to standard iOS/Material toggles which use a 2:1 or
        1.75:1 width:height ratio. 44:24 = 1.83:1 is fine but the knob
        leaves 20px of track = only 2px of visible track gap around the
        knob, making it look cramped.

FIX PLAN:
  File: launcher/app/components.css (lines 605–643)

  A. Resize the switch to 40×22px with a 16px knob, giving 2px padding
     and leaving 18px travel = a visible gap of ~2px around the knob.
     OR keep 44×24 but use a 16px knob so the gap is more visible.

  B. Use higher-contrast colours:
     - OFF background: use a darker track, e.g. var(--surface-4) or a
       dedicated `--switch-track` token.
     - OFF knob: white or near-white (`var(--text-on-accent)` or #fff).
     - ON background: var(--accent) (solid, not --accent-soft).
     - ON knob: white (#fff).
     This matches iOS/Material conventions where the toggle is obviously
     a toggle, not a faint outline.

  C. Add a subtle box-shadow to the knob:
       box-shadow: 0 1px 3px rgb(0 0 0 / .2);
     This gives the knob depth and makes it look grabbable.

  D. Verify the RTL travel calculation is correct:
     - In an RTL inline-flex, the span starts at the right.
     - `translateX(calc(-100% - 2px))` = -18px = moves left. ← CORRECT.
     - The existing RTL rule is a duplicate of the base rule; REMOVE the
       `[dir="rtl"]` override entirely since the app is RTL-only and the
       base rule already handles it correctly. Having two identical rules
       is confusing.

  E. Fix `flex: 0 0 44px` → update to match new width if resized.

 §3  ISSUE 1 — MCF OBLIGATIONS FILTER FIX [STATUS: DONE ✅]
────────────────────────────────────────────────────────────────────────────────

PROBLEM:
  The MCF obligations scraper could not switch the filter control from
  "لم يتم التقديم" (Not Filed) to "الكل" (All). The obligation reconciliation
  was skipped entirely, producing incomplete data (~36 obligations instead
  of 168).

ROOT CAUSE:
  1. navigateToHash() used `window.location.hash = route` which does NOT work
     from the SAP launchpad (tile container). The hash sets but the app
     doesn't navigate — you must CLICK the tile.
  2. switchSelectFilter() used page.evaluate to find the UI5 Select control
     in the registry, but the browser context sometimes can't see the
     registry → returns `control_matches_0`.
  3. The popover list item text matching for "الكل" failed because items
     have embedded count text.

FIX APPLIED (3 files):

  obligations-scraper.js:
    - Rewrote _applyFilter() to use direct Playwright locator strategy:
      1. Find `.sapMSlt:not(.sapMSltHiddenSelect)` → click
      2. Wait 800ms for popover
      3. Find `li` with hasText: /^الكل/ → click
      4. Wait 2000ms for table reload
    - Added tile click after navigateToHash() for launchpad handling.
    - Label pre-check: if `.sapMSltLabel` already contains "الكل", skip.

  ui5-helpers.js:
    - Rewrote navigateToHash() (~L869) to use Home button → tile click
      → hash fallback pattern.
    - Enhanced switchSelectFilter() with broader DOM selectors and
      Playwright locator Strategy 3 fallback.

  documents.js:
    - Enhanced _verifyFilterApplied() with fast-path Playwright locator
      check for `.sapMSltLabel` containing "الكل" before the heavy
      page.evaluate() UI5 registry path.
